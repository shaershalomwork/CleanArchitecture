01 / Understand the starting point

A small application path to follow

The customer APIs are working examples of reads, writes, validation, permissions, and an overview enriched with optional billing information.

ProjectPut this here
WebRoutes, request/response DTOs, authentication, authorization, and HTTP mapping.
ApplicationUse cases, validation, and the narrow source interfaces those use cases need.
InfrastructureThe Development in-memory store, HTTP billing adapter, and shared source execution.
DomainApplication-owned business rules and models when needed. It starts intentionally empty.
examples/DatabasesOptional SQL Server, Oracle, and SQLite projects with their queries, connections, health checks, and tests.

A request follows Web endpoint → Application handler → source adapter → HTTP response. Existing MediatR dispatch and validation provide this path. Reuse the concrete example before adding another abstraction.

Web is the default startup project. AppHost is an optional Aspire launcher, ServiceDefaults supplies health and telemetry, and Shared holds orchestration names. An API-only first run needs no Node, Docker, database, billing service, or telemetry backend. Package restore may need access to your NuGet feed.

02 / Run and explore

Initial setup

Install a .NET SDK compatible with global.json. From the repository or generated application root, trust the local HTTPS certificate once and start Web:

dotnet --version
dotnet dev-certs https --trust
dotnet run --project src/Web --launch-profile https

The HTTPS launch profile sets ASPNETCORE_ENVIRONMENT=Development. Open the address printed by Web, then /scalar for the API reference. Generated applications may use different ports.

Development sample mode is simulated.

CustomerRegistry and Billing use Mode=Fake in appsettings.Development.json. The registry starts empty, is shared by requests in one process, and loses changes on restart. Billing returns a fixed sample balance. Startup logs identify simulated sources. Fake sources are rejected outside Development, including an environment named Test. Automated tests use Development.

Create and read your first customers

Local sign-in defaults to a read-only profile. This walkthrough selects reader-writer, keeps the session cookie, and obtains the antiforgery token required for cookie-authenticated writes. Development sessions expire quickly; sign in again and get a new token if necessary.

# PowerShell 7: use the HTTPS address printed by Web.
$base = 'https://localhost:5001'
Invoke-WebRequest "$base/auth/login?profile=reader-writer&returnUrl=/scalar" -SessionVariable session | Out-Null
$csrf = Invoke-RestMethod "$base/auth/antiforgery" -WebSession $session
$headers = @{ 'X-CSRF-TOKEN' = $csrf.token }

# The first list is empty. POST creates state in this process only.
Invoke-RestMethod "$base/api/customers" -WebSession $session
foreach ($id in @('CUST-001', 'CUST-WARN')) {
    $body = @{ customerId = $id; displayName = 'Example Customer' } | ConvertTo-Json
    Invoke-RestMethod "$base/api/customers" -Method Post -WebSession $session -Headers $headers -ContentType 'application/json' -Body $body
}
Invoke-RestMethod "$base/api/customers" -WebSession $session
Invoke-RestMethod "$base/api/customers/CUST-001/overview" -WebSession $session
Invoke-RestMethod "$base/api/customers/CUST-WARN/overview" -WebSession $session

Invoke-RestMethod "$base/api/customers/CUST-001" -Method Patch -WebSession $session -Headers $headers -ContentType 'application/json' -Body '{"displayName":"Updated customer"}'
Invoke-RestMethod "$base/api/customers/CUST-001" -Method Delete -WebSession $session -Headers $headers

Creating an existing ID returns 409. After deletion its overview returns 404. Restart Web and the list is empty again.

ExampleWhat is simulated
CUST-001, after POSTOverview succeeds with a fixed billing balance of 125.50 USD.
CUST-WARN, after POSTBilling reports a simulated timeout. HTTP 200 has status Warning and null unavailable billing fields.
CUST-FAILReserved failure scenario: overview returns 503; a write reports CUSTOMER.OUTCOME_UNKNOWN (502).
CUST-MISSINGReserved missing-customer scenario: overview returns 404. This ID cannot be registered.
Any other registered IDNormal in-memory CRUD with the fixed sample billing balance.
Generate an application from the organizational package

Use the version supplied by your organization. Maintainers can package this repository using build/repack.ps1; see the root README.

dotnet new install DataCentric.Integration.Solution.Template --version <approved-version>
dotnet new di-sln -n MyApplication -cf None

-cf None and --CustomerProvider None are defaults. No database provider is referenced. Optional database examples remain outside the default solution under examples/Databases.

03 / Build one feature

Add an API using the existing pattern

This exercise adds GET /api/customers/{customerId}/profile to your own application. It is a tutorial, not an extra baseline endpoint. Replace CleanArchitecture with your generated namespace.

1. Add a query, validator, and handler

The profile reuses the customer source, so it needs no new database code or interface. Validation checks input without I/O; cancellation flows to the adapter.

src/Application/Customers/Queries/GetCustomerProfile/GetCustomerProfile.cs
using FluentValidation;
using MediatR;
using CleanArchitecture.Application.Common.Results;
using CleanArchitecture.Application.Customers.Sources;

namespace CleanArchitecture.Application.Customers.Queries.GetCustomerProfile;

public sealed record GetCustomerProfileQuery(string CustomerId)
    : IRequest<OperationResult<Customer>>;

public sealed class GetCustomerProfileQueryValidator
    : AbstractValidator<GetCustomerProfileQuery>
{
    public GetCustomerProfileQueryValidator()
    {
        RuleFor(x => x.CustomerId).NotEmpty().MaximumLength(50)
            .Matches("^[A-Za-z0-9-]+$")
            .WithErrorCode("CUSTOMER.INVALID_ID");
    }
}

public sealed class GetCustomerProfileQueryHandler(ICustomerSourceAdapter customers)
    : IRequestHandler<GetCustomerProfileQuery, OperationResult<Customer>>
{
    public Task<OperationResult<Customer>> Handle(
        GetCustomerProfileQuery request, CancellationToken cancellationToken)
        => customers.GetCustomerAsync(request.CustomerId, cancellationToken);
}

2. Add the endpoint and its public response

Endpoint discovery registers IEndpointGroup implementations automatically. Keep a named handler for a stable OpenAPI operation ID, declare authorization, and use the existing response mapper.

src/Web/Endpoints/CustomerProfiles.cs
using MediatR;
using CleanArchitecture.Application.Common.Interfaces;
using CleanArchitecture.Application.Customers.Queries.GetCustomerProfile;
using CleanArchitecture.Web.Contracts;
using CleanArchitecture.Web.Infrastructure;

namespace CleanArchitecture.Web.Endpoints;

public sealed class CustomerProfiles : IEndpointGroup
{
    public static string RoutePrefix => "/api/customers";

    public static void Map(RouteGroupBuilder group)
    {
        group.RequireAuthorization("CustomerOverview.Read");
        var endpoint = group.MapGet(GetCustomerProfile, "{customerId}/profile")
            .Produces<ApiOperationResponse<CustomerProfileResponse>>();
        foreach (var status in new[] { 400, 401, 403, 404, 500, 502, 503, 504 })
            endpoint.Produces<ApiOperationResponse<CustomerProfileResponse>>(status);
    }

    [EndpointSummary("Get a customer profile")]
    [EndpointDescription("Requires customers.read. Returns a registered customer without requesting billing.")]
    public static async Task<IResult> GetCustomerProfile(
        ISender sender, ICorrelationContext correlation,
        string customerId, CancellationToken cancellationToken)
    {
        var result = await sender.Send(
            new GetCustomerProfileQuery(customerId), cancellationToken);
        return result.ToHttp(customer => new CustomerProfileResponse(
            customer.Id, customer.DisplayName, customer.ObservedAt), correlation.Id);
    }
}

public sealed record CustomerProfileResponse(
    string CustomerId, string DisplayName, DateTimeOffset ObservedAt);

3. Test through HTTP

Add this test to the existing functional test project. Its identity header is available only in the test host. Register the customer explicitly before expecting a successful read.

tests/Application.FunctionalTests/Customers/CustomerProfileTests.cs
using System.Net;
using System.Net.Http.Json;
using System.Text.Json;
using CleanArchitecture.Application.FunctionalTests.Infrastructure;

namespace CleanArchitecture.Application.FunctionalTests.Customers;

public class CustomerProfileTests
{
    [Test] public async Task ReadsARegisteredProfile()
    {
        await using var factory = new WebApiFactory();
        using var client = factory.CreateClient(new() { BaseAddress = new("https://localhost") });
        await CustomerFixtures.RegisterAsync(factory.Services, "CUST-001");
        client.DefaultRequestHeaders.Add("X-Test-User", "reader");
        using var response = await client.GetAsync("/api/customers/CUST-001/profile");
        response.StatusCode.ShouldBe(HttpStatusCode.OK);
        var json = await response.Content.ReadFromJsonAsync<JsonElement>();
        json.GetProperty("status").GetString().ShouldBe("Success");
        json.GetProperty("data").GetProperty("customerId").GetString().ShouldBe("CUST-001");
    }
}

Also cover missing customers (404), invalid IDs (400), unauthenticated callers (401), and missing read permission (403). The saved API contract protects existing operations; approve the intentional new route in that fixture while retaining existing entries. Build Web and, for Angular, run npm --prefix src/Web/ClientApp run generate-api.

For a write API, follow the customer commands and require a write policy. Keep transactions inside the database adapter and preserve the no-automatic-retry policy for writes.

04 / Add persistence when needed

Connect a real database explicitly

The base application references no database driver or Dapper packages. Each optional project owns its driver, connection lifetime, provider error mapping, and readiness probe. All implement the existing customer source interfaces. Choosing a provider does not enable Live mode automatically.

Start with SQLite

For a new application, dotnet new di-sln -n MyApplication --CustomerProvider SQLite adds the reference and registration. To add SQLite to an existing base application:

dotnet add src/Web/Web.csproj reference examples/Databases/SQLite/SQLite.csproj

In Web's Program, after builder.AddInfrastructureServices() and before builder.Build(), add:

builder.Services.AddSqliteCustomerRegistry();

Use the optional SQLite CLI to prepare a disposable file, then select Live mode. The application does not create or migrate databases on startup.

New-Item -ItemType Directory -Force artifacts | Out-Null
sqlite3 artifacts/customer-registry.db ".read docs/customer-registry.sqlite.sql"
$database = (Resolve-Path artifacts/customer-registry.db).Path
$env:ConnectionStrings__CustomerRegistry = "Data Source=$database"
$env:Sources__CustomerRegistry__Provider = 'SQLite'
$env:Sources__CustomerRegistry__Mode = 'Live'
dotnet run --project src/Web --launch-profile https

Customer reads and writes now use the file; Billing still uses the Development simulation. The startup notice identifies simulated sources. Reads use read-only connections; writes use a separate ReadWrite connection that refuses to create a missing file. See SQLite details.

SQL Server and stored procedures

Generate with --CustomerProvider SqlServer, or add its project reference and call builder.Services.AddSqlServerCustomerRegistry(). The source must expose the schema and procedures illustrated by the disposable fixture. Only run that fixture against a separate example database.

$env:Sources__CustomerRegistry__Provider = 'SqlServer'
$env:Sources__CustomerRegistry__Mode = 'Live'
$env:ConnectionStrings__CustomerRegistry = 'Server=<host>;Database=<database>;Integrated Security=true;Encrypt=true;TrustServerCertificate=false'
dotnet run --project src/Web --launch-profile https

This assumes Windows authentication and a trusted server certificate. Use your actual authentication method and keep secrets in Web user secrets or your deployment secret provider. Sources:CustomerRegistry:ConnectionName defaults to CustomerRegistry, naming the entry under ConnectionStrings.

This compiled example shows bound query parameters and stored-procedure execution. Procedure return codes are source-specific: this fixture uses 0 for success and 404 for absence.

examples/Databases/SqlServer/SqlQueryExamples.cs
using System.Data;
using CleanArchitecture.Infrastructure.Execution;
using Dapper;
using Microsoft.Data.SqlClient;

namespace CleanArchitecture.Infrastructure.Sources.CustomerRegistry;

// Executable examples of database calls; registered adapters also map results and errors.
public static class SqlQueryExamples
{
    public sealed class CustomerRow
    {
        public string Id { get; set; } = "";
        public string DisplayName { get; set; } = "";
    }

    public static Task<CustomerRow?> FindWithQueryAsync(SqlConnection connection, string customerId, CancellationToken token) =>
        connection.QuerySingleOrDefaultAsync<CustomerRow>(new CommandDefinition(
            "SELECT Id, DisplayName FROM dbo.Customers WHERE Id = @CustomerId",
            new { CustomerId = customerId }, commandTimeout: 3, cancellationToken: token));

    public static async Task<CustomerRow?> FindWithProcedureAsync(SqlConnection connection, string customerId, CancellationToken token)
    {
        var parameters = new DynamicParameters();
        parameters.Add("@CustomerId", customerId, DbType.String, size: 50);
        parameters.Add("@ReturnCode", dbType: DbType.Int32, direction: ParameterDirection.ReturnValue);
        var row = await connection.QuerySingleOrDefaultAsync<CustomerRow>(new CommandDefinition(
            "dbo.GetCustomer", parameters, commandType: CommandType.StoredProcedure,
            commandTimeout: 3, cancellationToken: token));
        var code = parameters.Get<int>("@ReturnCode");
        if (code == 404 && row is null) return null;
        if (code != 0 || row is null || row.Id != customerId || string.IsNullOrWhiteSpace(row.DisplayName))
            throw new SourceFailureException("INVALID_RESPONSE");
        return row;
    }
}

The caller owns the open connection. The existing SqlConnectionFactory opens a lease per execution attempt, sets correlation context, and clears/disposes it with await using. Registered adapters wrap calls in the shared executor, map outcomes to the API envelope, and use transactions for writes. These helpers illustrate database calls and do not add endpoints.

See Oracle setup for its connection settings and schema. Changing only the runtime Provider setting cannot install a driver: add its project and registration first. Missing Live configuration or implementation causes an actionable startup error, with no fallback to Fake.

Connecting billing and preparing a deployment

Configure Sources:Billing:Mode=Live, an HTTPS BaseUrl ending in /, and its ApiKey. Outside Development, both sources must be Live and authentication uses the existing external identity configuration. See integration details and authentication.

Writes never retry automatically. A timeout or disconnected write can occur after commit and returns CUSTOMER.OUTCOME_UNKNOWN; reconcile before retrying. Preserve provider error mapping and transaction behavior when adapting examples to your schema.

Use PowerShell 7. Default checks include architecture and API contracts. Optional tests live under examples/Databases/Database.Tests, outside the base dependency graph. The package matrix checks all four provider choices and both client variants.

Customer responses retain status, data, issues, and correlationId, with X-Correlation-ID on responses. Successful writes stay HTTP 200; PATCH accepts a displayName object. Authentication endpoints retain their own shapes. /alive checks liveness; /health checks readiness.
